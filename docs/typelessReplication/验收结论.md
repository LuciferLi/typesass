## 2026-08-15 CodexMan 0.1.1 麦克风主动授权修复发布验收

结论：通过，0.1.1 已修复“只打开系统麦克风设置但 CodexMan 不出现在授权列表”的问题，并完成 Tauri macOS 官网发布。

风险等级：L2。

判断依据：

- 本批直接影响 macOS 麦克风 TCC 授权触发，是语音输入核心前置链路。
- 改动范围集中在 Tauri 原生授权命令、前端权限入口和版本发布，不涉及远端接口、数据库或模型契约。

问题原因：

- 0.1.0 的 `is_microphone_authorized()` 只读取 AVFoundation 授权状态，不主动触发系统授权弹窗。
- `open_microphone_settings()` 只打开 macOS 麦克风设置页；如果 App 从未主动请求过麦克风，macOS 不会把 CodexMan 加入列表，因此用户看不到开关。

本批改动：

- 为 `objc2-av-foundation` 启用 `block2` feature，并新增 `block2` 依赖。
- 新增 Tauri 命令 `request_microphone_access`，通过 `AVCaptureDevice::requestAccessForMediaType_completionHandler` 主动请求麦克风授权。
- 权限页点击麦克风授权时，先主动请求系统弹窗；用户拒绝或系统已拒绝时，再打开 macOS 麦克风设置页。
- 语音任务开始前执行 `ensure_microphone_access_for_voice`，保证用户直接按语音快捷键也会触发系统授权，而不是录制静音或只提示未授权。
